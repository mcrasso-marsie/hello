# Discovery Graph: DG-0002
**Graph Type:** opportunity

## Core Issue

Users of the wordcount tool need both word counts and non-whitespace character counts reported by default when inspecting a file, whereas the tool currently reports only the word count.

**Impact/Value:** Enables users to see both word count and non-whitespace character count in a single default invocation without needing a separate tool or extra flags.

**Discovery Method:** Direct user feature request and clarification Q&A.

## Patterns

### Pattern 1: non-whitespace-character-counting

**Applies To:** Text counting capability (hello package)  
**Frequency/Recurrence:** Every counting invocation  
**Severity/Urgency:** Normal  
**Confidence:** High  
**Current State:** Only whitespace-separated word counting is supported; no character count is computed.  

**Evidence Signals:**

- Users want to count non-whitespace characters (excluding whitespace, returns, etc.) in addition to words.

### Pattern 2: default-dual-count-output

**Applies To:** wordcount CLI default output behavior  
**Frequency/Recurrence:** Every default CLI invocation  
**Severity/Urgency:** Normal  
**Confidence:** High  
**Current State:** Running wordcount PATH prints only the integer word count followed by a newline.  

**Evidence Signals:**

- Running wordcount PATH should output both the word count and the character count by default rather than only the word count.

## Pattern Dependency Graph

Reporting both counts by default in the CLI relies on establishing the non-whitespace character-counting capability alongside existing word counting.
