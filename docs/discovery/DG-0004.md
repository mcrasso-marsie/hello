# Discovery Graph: DG-0004
**Graph Type:** opportunity

## Core Issue

Users can count only a named file. They cannot count text piped into wordcount through standard input.

**Impact/Value:** Stdin input lets wordcount join shell pipelines without temporary files. It closes a gap deferred across three strategy documents.

**Discovery Method:** Written feature request in the handoff, checked against STRAT-0001..0003 non-goals and SPEC-0001..0003.

## Patterns

### Pattern 1: stdin-counting

**Applies To:** wordcount command-line interface (hello.cli)  
**Frequency/Recurrence:** Every pipeline use of wordcount  
**Severity/Urgency:** Medium  
**Confidence:** High  
**Current State:** wordcount accepts only one PATH argument and reads only from that file.  

**Evidence Signals:**

- Running `wordcount -` reads UTF-8 text from standard input instead of a file path.
- Standard input was deferred as a non-goal in STRAT-0001, STRAT-0002 and STRAT-0003, and this work item takes it up.
- Input read from stdin prints the same `words: <N> characters: <M> lines: <L>` line, using the existing word, character and line rules.
- Empty stdin prints `words: 0 characters: 0 lines: 0`.
- The README and acceptance tests must be updated to cover stdin input.

### Pattern 2: stdin-invalid-utf8-error

**Applies To:** wordcount error output for stdin input  
**Frequency/Recurrence:** Whenever non-UTF-8 bytes are piped in  
**Severity/Urgency:** Medium  
**Confidence:** High  
**Current State:** Invalid UTF-8 handling exists only for files, with a message naming the file PATH.  

**Evidence Signals:**

- Invalid UTF-8 on stdin is a file-style error with exit status 1 that names `<stdin>`.

### Pattern 3: no-argument-usage-preserved

**Applies To:** wordcount argument parsing  
**Frequency/Recurrence:** Every invocation without arguments  
**Severity/Urgency:** High  
**Confidence:** High  
**Current State:** No argument prints argparse usage to stderr and exits with status 2.  

**Evidence Signals:**

- Running `wordcount` with no argument stays a usage error with exit status 2.

## Pattern Dependency Graph

Stdin counting is the root pattern. The invalid UTF-8 error on stdin only exists once stdin can be read. Keeping the no-argument usage error is a constraint on how stdin counting is invoked. The README and test updates follow from stdin counting.
