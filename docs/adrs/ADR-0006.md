# ADR-0006: Labeled combined success output for wordcount

## Context

Users need both counts from the existing invocation without flags, so the success output must carry two values and cannot remain a bare integer.

## Decision

We will print exactly one labeled line, `words: <N> characters: <M>`, on stdout for every successful invocation of wordcount, and we accept that this breaks consumers that parsed the earlier bare integer.

## Alternatives Considered

- Keep the bare word count by default and add a flag for characters: rejected, it conflicts with the no-flags, always-both requirement
- Provide a separate command for character counting: rejected, users would need an extra action
- Print two lines: rejected, a single line is simpler for consumers to parse and was the requested form

## Consequences

### Positive

- Both measures are available in every successful invocation
- Labels make the output self-describing

### Negative

- Consumers that parse a bare integer break and must be updated
- The labeled format becomes a contract that later changes must treat as breaking
