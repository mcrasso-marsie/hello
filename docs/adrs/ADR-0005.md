# ADR-0005: Labeled two-line default output for wordcount

## Context

Replacing SPEC-0001's lone integer stdout output with dual-metric reporting affects CLI consumers, existing tests, and any future CLI features that extend wordcount output.

## Decision

We will emit default wordcount stdout as two labeled lines: `words: <word_count>` followed by `non-whitespace chars: <char_count>`.

## Alternatives Considered

- Print two space-separated integers ('<word_count> <char_count>'): rejected because unlabeled numbers are ambiguous to readers and downstream scripts.
- Keep single word-count output as default and expose non-whitespace character counting behind an opt-in flag: rejected per STRAT-0002 because users require both metrics by default in a single invocation.

## Consequences

### Positive

- Both metrics are self-identifying on stdout for human inspection and unambiguous to parse by label.
- Establishes a consistent `label: value` output pattern for any future CLI extensions.

### Negative

- Breaks backward compatibility with SPEC-0001 callers and existing tests that expect a single bare integer on stdout.

## Compliance and Verification

| Rule enforced | Type | Mechanism | Scope |
|---------------|------|-----------|-------|
| Successful default `wordcount PATH` execution writes `words: <word_count>\\nnon-whitespace chars: <char_count>\\n` to stdout. | DETERMINISTIC | tests/test_cli.py::test_default_output_reports_words_and_non_whitespace_chars | word-count-command |
