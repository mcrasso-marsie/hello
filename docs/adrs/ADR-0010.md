# ADR-0010: Four-field labeled success output for wordcount (supersedes ADR-0008)

## Context

ADR-0008 fixes a three-field line. Users want the byte size beside the character count, and approved the order words, characters, bytes, lines.

## Decision

We will print exactly one labeled line, `words: <N> characters: <M> bytes: <B> lines: <L>`, on stdout for every successful wordcount run, and never print a count on error. This supersedes ADR-0008.

## Alternatives Considered

- Append bytes after lines: rejected, the user asked for bytes beside characters
- Opt-in flag for bytes: rejected, it adds an argument and hides the field by default
- Keep ADR-0008 and use a second tool: rejected, it leaves the problem unsolved

## Consequences

### Positive

- One run gives all four counts
- The field order follows the user's request

### Negative

- Scripts matching the three-field line break after upgrading
- Existing tests that assert the three-field line must change

## Compliance and Verification

| Rule enforced | Type | Mechanism | Scope |
|---------------|------|-----------|-------|
