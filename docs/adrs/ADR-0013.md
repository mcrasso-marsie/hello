# ADR-0013: Longest-line measure reuses the word rule and terminator set in a pure counter

## Context

A second definition of a word or a terminator would make the output fields disagree on edge input. The measure must also stay free of I/O, as the other counters do.

## Decision

We will compute the longest-line word count in the pure function hello.longest_line.longest_line_words. It reuses hello.counter.count_words and hello.lines.LINE_TERMINATORS and counts an unterminated final segment as a line for this measure only.

## Alternatives Considered

- Give the measure its own word definition, such as splitting on spaces only: rejected, fields could disagree on the same input.
- Use str.splitlines() directly: rejected, the terminator set must stay explicit and not depend on library behavior (ADR-0007).
- Change count_lines to count the final segment: rejected, it changes a shipped field and the SPEC-0003 rule.
- Use an external tool or package such as wc -L: rejected, it adds a dependency and measures display width, not words.

## Consequences

### Positive

- Words, lines and the longest line share one set of definitions.
- The measure is testable without I/O.

### Negative

- Two fields treat the final unterminated segment differently, and the README must explain it.
- A new module and an import link from hello.longest_line to hello.lines.
