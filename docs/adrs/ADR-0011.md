# ADR-0011: Raw-byte rule in a pure byte counter

## Context

Standard input has no file-system size and cannot be read twice. Re-encoding decoded text measures the decoded text, not the input.

## Decision

We will count bytes in a pure function hello.byte_counter.count_bytes in src/hello/byte_counter.py. It receives the raw bytes of the single input read, never a re-encoding or a file-system size.

## Alternatives Considered

- Take the size from os.stat: rejected, stdin has none, so file and '-' would diverge
- Re-encode the decoded text: rejected, it could drift from the raw input
- Compute len() inline in hello.cli: rejected, it breaks the pure-counter pattern of ADR-0002, ADR-0005 and ADR-0007

## Consequences

### Positive

- File and '-' give the same count for the same bytes
- The byte rule is testable without I/O

### Negative

- A one-line function adds a module
- hello.cli must keep the raw bytes alongside the decoded text

## Compliance and Verification

| Rule enforced | Type | Mechanism | Scope |
|---------------|------|-----------|-------|
| hello.byte_counter performs no file, process or console I/O and imports only the standard library | DETERMINISTIC | tests/arch/test_layering.py::test_byte_counter_performs_no_io | byte-counter |
| hello.cli passes the bytes of its single read to count_bytes and never re-encodes text or reads a file-system size for it | AGENT-EVALUATED | Code review of src/hello/cli.py against this rule | word-count-command |
