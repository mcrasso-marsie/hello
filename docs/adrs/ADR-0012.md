# ADR-0012: Four-field labeled success output for wordcount

## Context

Users need the longest-line word count in every run. ADR-0008 fixes a three-field line, so adding a figure changes the shared output contract.

## Decision

We will print exactly one labeled line, `words: <N> characters: <M> lines: <L> longest_line_words: <K>`, on stdout for every successful wordcount run. This supersedes the three-field line of ADR-0008.

## Alternatives Considered

- Place the new field before or between existing fields: rejected, it shifts field positions and breaks parsers of the three-field line.
- Print the figure on a second line: rejected, it breaks single-line parsing.
- Add a flag to show the figure: rejected, it changes the single-argument invocation.

## Consequences

### Positive

- Users get the figure from one run, and the first three fields stay in place.

### Negative

- Consumers that match the three-field line exactly break.
- Tests, README and specs that assert the three-field line need edits.

## Compliance and Verification

| Rule enforced | Type | Mechanism | Scope |
|---------------|------|-----------|-------|
| The success line has the four labeled fields in order. | DETERMINISTIC | tests/test_cli.py::test_success_line_is_four_labeled_fields_in_order | word-count-command |
