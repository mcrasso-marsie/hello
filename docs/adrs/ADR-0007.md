# ADR-0007: Explicit line-terminator rule in a pure line counter

## Context

Users want a line count from wordcount. Human review required the terminator set to be enumerated rather than inherited silently from str.splitlines(), and the architecture keeps each counting rule in its own pure unit (ADR-0002, ADR-0005).

## Decision

We will define a line as a segment ended by a terminator from an explicitly enumerated set. The set is LF, CR, CRLF (one terminator), VT, FF, FS, GS, RS, NEL, LS and PS, and an unterminated final segment is not counted. We will implement this as the pure function hello.lines.count_lines with the constant hello.lines.LINE_TERMINATORS in src/hello/lines.py, separate from the word counter, the character counter and all I/O.

## Alternatives Considered

- Count with len(text.splitlines()) and adjust for the final segment: rejected, because the contract would then depend silently on interpreter behaviour, which human review rejected.
- Count only LF as wc -l does: rejected, because the owner chose the broader Unicode-aware rule in DG-0003.
- Count segments including an unterminated final segment: rejected, because it contradicts the confirmed example 'a\nb' → 1.
- Fold line counting into hello.counter or hello.characters: rejected, because it blurs the one-rule-per-counter boundary and risks regressing the word and character results.

## Consequences

### Positive

- The line rule is reviewable in one place and does not change silently across Python versions.
- The cross-check test surfaces any future divergence from str.splitlines() as a test failure.
- Line counting is testable without files and cannot affect error paths.

### Negative

- Counts differ from wc -l on files with CR, FF, NEL, LS, PS or FS/GS/RS, which may surprise users.
- The enumerated set must be maintained by hand if the project ever wants to track a changed interpreter definition.
- The full code-point cross-check scan adds some test runtime.

## Compliance and Verification

| Rule enforced | Type | Mechanism | Scope |
|---------------|------|-----------|-------|
| hello.lines performs no file, process or console I/O and imports only the standard library | DETERMINISTIC | tests/arch/test_layering.py::test_line_counter_performs_no_io | line-counter |
