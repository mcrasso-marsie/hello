# ADR-0008: Three-field labeled success output for wordcount (supersedes ADR-0006)

## Context

ADR-0006 fixed the success line as `words: <N> characters: <M>`. DG-0003 and STRAT-0003 require the line count to always appear on the same line, with no new flag.

## Decision

We will print exactly one labeled line, `words: <N> characters: <M> lines: <L>`, on stdout for every successful invocation of wordcount, and never print any count on error. This supersedes ADR-0006's two-field line, and we accept that it breaks consumers that match `words: <N> characters: <M>` exactly.

## Alternatives Considered

- Opt-in --lines flag: rejected, because it changes the invocation surface and contradicts the approved no-new-flag requirement.
- Print the line count on a separate stdout line: rejected, because it breaks the agreed one-line report.
- Keep the two-field line and add a separate command: rejected, because users would still need two invocations.

## Consequences

### Positive

- Users get all three counts from one invocation on one line.
- Labels keep the output self-describing and extensible.

### Negative

- Scripts and tests matching the old two-field line break and must be updated.
- ADR-0006 must be marked superseded once this ADR is accepted.

## Compliance and Verification

| Rule enforced | Type | Mechanism | Scope |
|---------------|------|-----------|-------|
| A successful wordcount run prints exactly one stdout line matching `^words: \\d+ characters: \\d+ lines: \\d+\\n$`, with empty stderr and exit 0 | DETERMINISTIC | tests/test_cli.py::test_success_output_is_one_labeled_three_field_line | word-count-command |
